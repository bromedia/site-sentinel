# Source review: hosting usability and scan coverage

Reviewed base: `76bbbd5ce3939cf43235812bb91a7d23780b1f5c` (version 0.1.0). This is a focused source review and local regression exercise, not a penetration test or an audit of a deployed WordPress site.

## Addressed in this change

1. **Full scans skipped analysis of unchanged trusted files.** `Differ::compare` returned no event for a matching hash, so `Monitor` never passed the file to current signatures/checksums. A new rule could therefore miss an existing trusted payload indefinitely. Full scans now reanalyse unchanged records without accepting them anew or generating false edit warnings. Tests cover new signatures, an already-baselined core mismatch, upload images, deduplication and resumption.
2. **Stream HTTP fallback lost response status on the tested PHP 8.3 runtime.** `get_defined_vars()['http_response_header']` returned no useful response headers. Directly reading the local response-header variable fixes this; the existing real HTTP test exercises GET and POST with both transports.
3. **Generated cron assumed PATH and unquoted paths, and hid stderr.** Shared hosts can use a different PHP version in cron; spaces/apostrophes break unquoted paths and cron treats `%` specially even inside shell quotes. Init and the new `cron` command use the running PHP binary, proper escaping, and preserve stderr. A regression executes a generated command with unusual paths and verifies the arguments.
4. **No local setup diagnostic or coverage history.** `doctor` reports configuration/placement gaps and successful processing history without making network calls, sending messages or modifying state. Scan history separates partial progress from the last complete traversal. It does not certify that cron is installed or all checks succeeded.
5. **No automated test/build deliverable.** CI tests PHP 7.4, 8.3 and 8.4, checks compatibility, builds/lints the standalone file and provides a downloadable artifact with its checksum and license. The first minimum-version run also exposed two existing runtime-dependent test assumptions: PHP 7.4 has no PHP 8 tokenizer IDs, and a missing executable can return 127 instead of failing proc_open with -1. Tests now verify the corresponding checks and failure behavior on either runtime.

## Follow-up implementation: 0.2

1. **Shared budgets and continuation:** bounded comparison/analysis batches; processed-prefix cursors; reduced HTTP/process timeouts; full continuation during scheduled quick checks; cross-slice held groups; resumable initialisation without activating incomplete baselines; failed-attempt history. Single file I/O, streaming baseline merges, atomic checkpoints and notifications can overrun a cooperative deadline; this is not an OS sandbox.
2. **Strict unverified updates:** false-by-default auto_accept_unverified_updates holds premium/custom changes despite version bumps. Official checksum matches remain automatic. Scoped accept is the deliberate review acknowledgement; the weaker old policy is an explicit opt-in surfaced by doctor.
3. **Optional database monitoring:** see [DATABASE.md](DATABASE.md). Literal-only configuration extraction, SELECT-only account support, connect/read/query timeouts, reviewed hash-only account/option baselines, resumable post pages, spam/code heuristics and new-post burst alerts. Credentials, SQL and raw account/post contents are withheld from alerts/state/errors. CI exercises real MySQL/MariaDB queries with a SELECT-only monitoring account.

Remaining coverage work: excluded directories, symlink targets, nonstandard WordPress layouts and expected core files missing before the initial baseline still need deliberate inventory improvements. The database module covers single-site tables/configured post types; multisite and arbitrary plugin tables are outside its first scope.

## Useful later improvements

- **Delivery tracking per channel:** `Alerter` considers a digest delivered when at least one eligible channel succeeds. A failed critical push channel may therefore not be retried immediately if email succeeds. Surface failures independently and retry by channel.
- **Reviewed update workflow:** changes to config/script currently require `accept --self`; consider a validated config-edit command that safely updates only the expected trust entry, with a diff and audit trail. Avoid blanket retrusting other files during unrelated changes.
- **Releases:** publish reviewed, versioned single-file release assets plus checksums so shared-hosting users need neither Git nor a local PHP build. The CI artifact is a first step, not a signed release/update service.

The same-account compromise limit remains fundamental: if an attacker can alter the script, config and baseline, self-checking is only a tripwire. Independent heartbeat/alert delivery and, where practical, a separately protected monitoring account provide stronger isolation.
